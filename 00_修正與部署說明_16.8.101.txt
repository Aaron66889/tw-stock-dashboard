台股戰情 16.8.101 同步修正版
日期：2026-10-13

這份 ZIP 是修正版原始碼；正式 Render 網站尚未由此次工作部署。

一、確認並修正的問題
1. 立即同步的控制變數沒有宣告，流程直接中斷。改用共享 Promise，重複點擊會等待同一次同步完成。
2. 同步 API 的 HTTP 200 / ok:false、HTML 回應或不完整交易格式曾被當成功。現在會顯示原因，保留本機交易與待同步隊列。
3. 同步期間的交易修改、新交易及刪除曾有被舊回應覆蓋的風險。現在只確認原本送出的那個版本，新的修改繼續待同步。
4. 雲端没有持股、但本機已有待同步成交時，初始化與上傳互相阻擋。現在可經明確確認，將整份本機持股與已包含的交易ID一併初始化，重試不重複加股。
5. 雙裝置更新採用條件寫入；保留每個成交ID，沒有或過期的持股版本不能覆蓋新雲端持股。
6. 交易刪除、平倉與上傳同時發生時，舊裝置不能讓刪除交易復活或重新打開平倉交易；平倉的股息損益也會保留。
7. 股息更新會合併事件與持股快照，較慢的回應不能覆蓋較新的快照。
8. 同步列分開顯示交易、持股、股息。三者全部确认才顯示「全部同步完成」，股息官方來源不足則顯示待齊。
9. 成分股查核 API 缺少官方來源判斷函式，已補上。ETF成分標籤中的數字鍵也改回字串代號。
10. 強勢加碼頁的現價沿用全站5～10秒行情；分數、突破位、執行帶、最高追價線仍跟隨30秒模型更新。
11. 網頁進入背景時停止新的輪詢；回到畫面會恢復必要資料及正在看的頁面。
12. 資料缺失顯示「—」，不再將 null 顯示成零；更新失敗不會把錯誤內容存成最後成功資料。
13. 回測切換ETF時，舊請求不能把結果放到新選取的ETF畫面。
14. 加入前後端版本檢查，避免只更新前端後，以舊後端處理新版持股初始化。
15. ZIP移除根目錄過期網頁副本，網頁只維護 public/。前後端與畫面版本統一為16.8.101。

四、部署方式
1. 解壓縮 ZIP，把專案資料夾內的檔案更新到原本 GitHub 專案根目錄，不能多包一層資料夾。
2. server.js、package.json 與整個 public/ 必須一起更新；測試檔位於 tests/。
3. 保留 Render 原本的 SUPABASE_URL、SUPABASE_SECRET_KEY、MODEL_SYNC_KEY 與其他環境設定。
4. 原本 build 為 npm install、start 為 npm start；不用換專案或資料庫。
5. 部署完成後，網址 /health 的 build 應為16.8.101-SYNC-RELIABILITY；網站頂部應為16.8.101 同步修正版。
6. 手機與電腦都重新整理，再各按一次立即同步，核對交易筆數、四檔股數與均價。
7. 如果待同步仍未消失，直接查看同步列保留的實際錯誤，不要用清除資料或強制覆蓋解決。
8. 只有顯示雲端尚未初始化時，才在持股正確的裝置按「上傳此裝置持股」，確認列出的股數和均價後初始化。
9. 股息顯示資料待齊時，表示官方配息來源未全部確認，不能直接當成程式同步失敗或全部成功。
